# Практика: почему UI показывает старый PR

Пользователь открыл A, затем B. B загрузился быстро, A — медленно. Наивный `await fetch; setReport` в конце показывает A.

1. Сами нарисуйте порядок событий и ожидаемый экран после каждого ответа.
2. Прочитайте [учебный loader](templates/report-loader.ts.example). Что означает generation? Почему сравнение выполняется перед show и showError?
3. Прочитайте [тесты](templates/report-loader.test.ts.example). Deferred promise даёт тесту точное управление порядком ответов. Это делает проверку повторяемой без sleep.
4. Уберите сравнение generation в копии. Тест «keeps B when A finishes later» должен перестать проходить. Верните сравнение и объясните причину.
5. Рассмотрите случай: B завершился ошибкой, A пришёл позже. Должна остаться ошибка B. Почему показывать A было бы неправильно?
6. Передайте неверный run_id и неизвестный status. `as Report` ничего не проверил бы; Zod и проверка идентификатора отклоняют ответ.

## Как запустить шаблон после настройки

Требуются согласованные версии Node, pnpm, TypeScript, Zod и Vitest. Их установка в приложение — отдельная задача. В отдельном временном учебном проекте установите эти зависимости, скопируйте два `.example` файла как `report-loader.ts` и `report-loader.test.ts`, затем выполните:

```sh
pnpm exec vitest run report-loader.test.ts
pnpm exec tsc --noEmit --strict --target ES2022 --module ESNext --moduleResolution bundler --skipLibCheck report-loader.ts report-loader.test.ts
```

Это тест модуля порядка ответов, а не React-компонента. В приложении дополнительно проверяются loading, доступность, cleanup эффекта и реальные DTO. Версии/результаты локальной проверки автора PR приводятся в PR; не переносите их автоматически на своё окружение.

Проверка образцов 2026-09-10 в отдельном временном проекте: Node 26.0.0, pnpm 11.19.0, Zod 4.6.0, Vitest 5.0.0, TypeScript 7.0.2, @types/node 22.20.2. Все 5 тестов и приведённый typecheck прошли. Это проверенные версии учебного окружения, а не предложение миграции приложения на них.
