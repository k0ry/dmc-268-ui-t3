Прочитай [правила](../../rules/frontend.md), [тест-план](../../templates/test-plan.md) и конфигурацию рабочей ветки. Vitest пока отсутствует в main; тестовый шаблон нельзя выдавать за выполненный тест приложения.

Проверяй наблюдаемое поведение: malformed JSON отвергнут, старый запрос не заменил текущий run, отказ не выглядит как пустой успех. Для гонки используй управляемые promises, а не случайные задержки. Пример: [report-loader.test.ts.example](../../templates/report-loader.test.ts.example).

Подменяй сетевую границу, сохраняя в тесте проверяемую логику. Для компонента проверяй действие и видимый результат доступными средствами проекта; библиотеки DOM/jsdom устанавливаются отдельной явной частью задачи. Разделяй typecheck, unit и интеграцию с backend — один уровень не доказывает другой.

На выходе: сценарии Given/When/Then, тесты по согласованному контракту, команды с фактическими результатами и список требуемых интеграций. Не запускай недоверенный PR в среде с секретами.
