# Тест-план frontend

Заполните: Issue → действие → ожидаемый результат → видимый сбой → уровень теста → команда → фактический результат.

| Given / When | Then | Как воспроизвести |
| --- | --- | --- |
| API вернул неверный DTO | Ошибка контракта, данные не в store | Вернуть неверный тип/неизвестный статус |
| A запрошен, затем B; B пришёл первым | На экране B после обоих ответов | Deferred promises, без sleep |
| A запросился, B завершился ошибкой, затем A пришёл | Ошибка B, не отчёт A | Явно управлять порядком завершения |
| Компонент размонтирован | Нет позднего обновления | Cleanup + завершение promise |
| Сервер вернул partial | Видно ограничение проверки | Fixtures по реальной API-схеме |
| Два нажатия rerun | Два действия по контракту; retry одного сохраняет ключ | Отдельные idempotency keys на явные действия |
| Клавиатура/экранный диктор | Кнопка и ошибка доступны | Проверка label, focus и семантики |

Пока Vitest не настроен, используйте таблицу как acceptance criteria. `.example` тесты требуют копирования и настройки зависимостей, а их DTO — согласования с backend.
